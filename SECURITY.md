# Security status

This fictional-data prototype implements storage, fixed-account authentication, queue/consent, reviewed clinical workflows, source-checked summary/local R4 output and own-patient audit access. Connected browser/hosting behavior and official FHIR validation remain unverified. Use fictional data only.

Implemented boundaries include private/generated-file exclusions, explicit public build/static roots, safe settings, private-path/symlink checks, schema/FK/append guards, bounded synchronous units, atomic audit/receipts and storage integrity verification. Startup opens only a verified existing file; it does not initialize/repair one. Maintenance requires a stopped cooperating backend and refuses overwrites/public destinations. Passwords use Argon2id with 19 MiB/time 2/parallelism 1 outside transactions; login permits one verification in flight and five failures per minute per bounded account/source pair. Restore ends recovered authorization and creates a new dataset branch.

Login stores a SHA-256 verifier for a 32-random-byte opaque cookie secret; receipts contain issuance references, never passwords, cookie secrets, CSRF values or Set-Cookie. Sessions have an absolute 7,200-second limit. Cookie attributes are HttpOnly, host-only, Path=/ and SameSite=Strict, with Secure except the explicit loopback HTTP configuration. Mutations require exact Origin, UUID key and JSON; authenticated mutations also require server-matched CSRF. Current actor/role/object checks precede receipts. Lost-cookie login replay requires credentials, ends the orphan and returns LOGIN_REAUTH_REQUIRED; it cannot recreate the cookie.

Shared guards enforce room/patient/encounter/session/grant bindings and expiry. Command, audit and receipt writes commit atomically; protected computations occur outside transactions, require a fresh audited authorization gate and expose a buffered result only through another current-authorization check. Real HTTP tests exercise consent decisions, assistance, expiry, revocation, closure, exact review/commit, source corrections and actual query/output/audit release races. These results do not complete S01–S14 or browser validation. Logout ends only the current browser session and its clinician requests/grants; patient logout preserves the sharing choice.

Summary/FHIR requires the exact COMMITTED reviewed batch, canonical capture hash, event/source/review bindings and current selected tips. A later selected-event correction/retraction refuses the old output. No original-source/history/query/check import occurs. Patient self-output continues after closure; clinicians need current patient-approved summary:export and an open encounter. Staff/assistants/emergency cannot export. One shared build and complete 1 MiB buffers bound generation; no streaming before audit/final permission check. Local application preflight and escaped XHTML do not establish official validation, clinical correctness, profile conformance or a signature. X-FHIR-Validation remains NOT_RUN.

Audit history/integrity/download requires matched patient:self on every call. Export appends its audit and snapshots every matched row through that ID in one transaction, then checksums outside SQL and rechecks ownership/session before delivery. Intervening own rows are included and other patients excluded; no recursive export audit or truncation is allowed. A detected clinical-chain mismatch returns safe FAIL, never a fixed seal. SHA-256 covers exact exported canonical content, not historical authenticity. The earlier clinician form of standalone integrity access has been narrowed to the final patient-only contract.

Manual/scripted capture requires assigned clinical:write and checked-in open encounter, independently of history sharing. Manual entry infers no items; scripted text retains simulation metadata with null confidence. Draft edits preserve original source, invalidate review and require a new exact hash/version review. One atomic reviewed batch per encounter is the only live append path. Prior-source changes additionally require current triage:read; unknown/unreadable targets fail safely. Review/source checks do not establish source truth. Ten capture permits are bounded through active persistence, including cancelled work. Clinical read receipts contain only safe IDs/as-of/ruleset references; replay rechecks current access and reconstructs the original snapshot. Unmapped/conflicting evidence has null certainty, and optional checks return NOT_EVALUATED with no safety assertion or commit gate.

Consent requests last at most 300 seconds and grants at most 900, both capped by the requesting session. Ask Why/clarify/polling/replay never renew deadlines. PHONE requires the matched patient; ASSISTED_QR requires independent assigned staff, actual patient-choice confirmations and server-derived assistant evidence. Clinician request/clarify/emergency replay fingerprints include their exact session. Transfer/absence/completion/withdrawal closes the old encounter and ends its access in one transaction. Public displays omit identity/encounter/consent fields. Emergency access checks the clinician's own seeded mock and grants only two read scopes after durable audit; it is not live registration verification or medical justification validation. [API notes](docs/API.md) document the implemented fields and limits.

The browser helpers retain CSRF and bounded uncertain intents in page memory, discard late replies after session/dataset changes and clear displayed clinical context on transport loss through registered page callbacks. Same-key automatic retries are limited to two additional attempts for transport loss or explicit 503 SAME_KEY, within a five-second retry-admission budget. Pages must register their clearing/rendering callbacks when implemented. No LocalStorage or service-worker clinical cache is introduced. Login credentials are discarded after the bounded request attempt.

Clinical hashes cover complete canonical envelopes and mirrored bindings. Triggers and checks provide tamper evidence under their stated limits; a host operator who replaces the database and chain can evade that evidence. Backup digests are not signatures, encrypted storage or an independent authenticity anchor. Private file modes are requested, but Windows ACL hardening/host security is not established by this stage.

Keep .env, keys, databases, sidecars, backups and clinical contents outside Git/static output/logs. .env.example is public and contains no secret. SARVAM_ENABLED defaults false; no real records or keys may enter browser code. Live provider activation requires verified promotional credit/key/access; no paid fallback is permitted. The user reported 100 credits and live synthetic checks succeeded. Local text is now explicitly enabled behind a private expiring confirmation; account balance is not automatically monitored or inferred from token usage.

The optional text adapter uses one fixed HTTPS host/model and no SDK/tools. Durable reservations precede egress; at most one call runs, three reservations/minute and thirty/dataset survive ordinary restart. Reservations remain consumed on provider failure, timeout or lost final audit; orphan intents cannot resubmit upstream. Current authorization precedes replay and final delivery. Question interpretation sends no vault, accepts only a topic, and computes cited evidence locally. Brief proposals use saved source/version hashes; history is opt-in under current vault:query consent and is rechecked before persistence/delivery. Notes/items stay intact; normal save/exact review/commit remains necessary. Literal quote/reference checks do not validate medical paraphrases. Free text may itself contain identifying details: fictional data only.

Provider requests/responses are bounded to 24 KiB context, 32 KiB complete request and 64 KiB response with a twenty-second deadline, strict structured validation and no automatic provider retry. Billing/auth/rate errors stop the adapter for that process. Standing credit is read afresh from an allowed private path or the fixed Render secret file: bounded descriptor reads, nonlink/identity checks, strict JSON and expiry within 24 hours of verification. The explicit operator command may create/replace a local confirmation; it never calls the provider, changes API keys or resets durable limits. Missing/invalid/expired confirmation disables AI while manual/local care continues. It is neither a balance API nor proof against billing. Ordinary tests use stubs; explicit live smoke uses a separate temporary confirmation. See docs/AI.md for evidence/renewal.

GET /api/v1/system/telemetry requires assigned staff/clinician queue permission and returns process RSS, bounded successful-query timings and capture count without patient values. It exposes no public profiler or test-control channel. The resource runner samples only its owned server child through private test IPC; sample gaps and insufficient data produce UNAVAILABLE rather than fabricated results. Shutdown drains for up to thirty seconds, then aborts outstanding provider work and closes remaining connections. Hosted signal delivery and persistence remain unverified.

The listener serves only frontend/assets and uses restrictive local-script/style CSP, no-store API responses, no-referrer and nosniff. CORS names the exact configured frontend origin with credentials; proxy headers are untrusted. Health checks reveal no dataset identifier or clinical counts and make no audit writes. Backward time disables protected access/readiness. Hosted browser SameSite/CORS/TLS/proxy/persistence behavior remains unverified; Node cookie adapters do not prove browser enforcement. Dependency/native smoke checks do not establish privacy compliance, real-person identity assurance or clinical safety.

The Render candidate adds no public initialization, profiler or maintenance API. Its normal entrypoint requires existing storage and validates same-origin HTTPS, one worker, private runtime paths and offline flags. Explicit initialization reads a <=8 KiB private Render secret file, refuses existing storage and opens the listener only after successful initialization. Temporary runtime maintenance uses the same stopped-process lease and new-output checks; restore is bound to the configured next database path. Management results are suppressed in service logs. The Render drain is 25 seconds within its documented platform window. These are local controls/tests and structural configuration, not proof of a mounted disk or hosted TLS/persistence.

Allocation tuning keeps Unicode/code-point v1 canonical ordering, duplicate-aware bounded parsing, full chain/source checks and current authorization gates. It removes intermediate arrays/repeated schema construction and reuses only envelopes verified within that same source call; no clinical result or permission cache is added. Persistent record bytes/hashes are not migrated. Private sampled-allocation diagnostics are opt-in and never expose an inspector port; the normal resource run uses no inspector or forced collection.
