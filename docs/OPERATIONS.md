## Reproducible local runtime

Use Node 24, `npm ci`, `npm run check:environment`, `npm run build`, then `npm test` as described in the README. Preserve an existing private .env. No install/build/start/test command initializes the working database or contacts an AI provider. Explicitly initialize through `npm run manage -- init --db data/runtime/vellum.sqlite3 --seed opd-demo-v1`, privately supplying the seven fixed account passwords. Then `npm start` verifies the existing file/map/public inputs and starts one listener.

Storage is one better-sqlite3 connection, WAL, synchronous FULL, foreign_keys ON and busy_timeout 50 ms. The database path must remain inside the App's allowed private data directories. Preserve the file and its SQLite sidecars together during ordinary operation; use stopped, verified maintenance rather than copying an active file. Backup/restore/reset commands and their new-path rules are in the README. Restore ends recovered access and pauses queues for reconciliation; it does not switch configuration automatically.

GET /api/v1/health/live is minimal liveness; /health/ready checks current storage/clock/draining state. Neither initializes storage or publishes clinical counts. SIGINT/SIGTERM stop new protected work, close idle connections and allow up to thirty seconds for active requests. The forced branch aborts provider work and closes remaining connections, then releases storage/lease. The actual held-request 30-second branch has a local HTTP test; platform signal delivery is separate evidence.

## Resource run

The user accepted 89.24 MB local peak RSS on 24 October 2026 and stopped further peak-memory tuning. [MEMORY.md](MEMORY.md) records the retained approaches, rejected experiment, full results and limits. The original 85 MB comparator stays unchanged for historical reporting; its miss is not an open local optimization task. Hosted measurements remain pending.

Close other protected test clients. Run this separately from npm test/build or another benchmark:

```powershell
npm run resource:smoke
npm run resource:profile
npm run resource:run
```

No arguments refuses to run. Smoke runs two requests/group and leaves every target UNAVAILABLE. Full mode takes about five minutes, using its own disposable database and Node child. It authenticates through ordinary login and one patient approval, without extending the 900-second grant, changing policy, using a fake clock or adding production endpoints. It generates private random passwords internally and never puts them in argv/reports. No provider is enabled.

Profile mode uses twenty requests/group and a private in-process inspector sampling session, without opening an inspector port. It records sampled allocated bytes (including collected objects), attributed app callsites and heap/external/array-buffer observations. It is diagnostic, not retained-memory accounting, clinical evaluation or a benchmark pass; all targets stay UNAVAILABLE. Sampling itself changes overhead/GC behavior. Full mode loads no inspector, samples actual RSS every 100 ms and adds memory-component observations every second, with no forced GC. These observations do not identify a leak or native allocator cause on their own.

Serving, deployment, test and resource npm commands select `--max-semi-space-size=1` on the pinned Node 24 runtime. This bounds each V8 nursery semi-space to 1 MiB; it does not cap RSS or old-space memory, reduce SQLite durability, or weaken Argon2. Smaller nurseries can increase GC work and promotion, so evaluate latency and full-process RSS together. The owned resource child inherits the driver's Node flags; its report records actual exec_argv and heap_size_limit. Running the driver directly without the flag measures a different runtime configuration. Node documents the [memory/throughput tradeoff and host-dependent defaults](https://github.com/nodejs/node/blob/v24.22.1/doc/api/cli.md#--max-semi-space-sizesize-in-mib); a 512 MiB Linux host may already choose 1 MiB by default. Local Windows savings therefore do not establish a Render improvement.

The resource-small-v1 fixture has two rooms, twenty patients/visits, one checked-in current plus nine waiting per room, and twenty valid events on distinct entity threads for the queried patient. Its penicillin-positive source is explicitly fictional; total dataset events are twenty-one. The report records counts, heads and fixture digest. It records Node/SQLite/settings, SHA-256 of backend/test JavaScript and lockfile, actual process PID, UTC bounds and workload duration. Source digests describe the measured version; subsequent edits require a fresh run for fresh evidence.

Groups run sequentially: VAULT_ACTIVE_STATE then VAULT_QUERY, each ten warmups and 120 measured complete HTTP responses. Consecutive clinical starts are at least 1,200 ms apart, with normal FULL/WAL/audit/receipts/permissions/rate limits. Queries use new deliberate keys, not answer-cache replays. Two nonoverlapping room-display pollers run every two seconds and count separately. There is no automatic workload retry; unexpected status/source/count stops the run with a failure code.

CLIENT_HTTP uses monotonic elapsed time through the full response body. Nearest-rank p95 is sorted[ceil(.95*N)-1]; at least 100 successful measured samples are required. Each group records attempts, completions, failures/timeouts, warmups, sample times, request/response body bytes and observed minimum start spacing. A complete successful group below 35 ms meets only that local latency target, not a hospital capacity claim. Captured runtime SERVER_REQUEST telemetry is separate and excludes transport/driver work.

RSS is sampled every 100 ms inside the owned server and sent through private test IPC. The driver checks PID and records baseline/peak/count, maximum server/receipt gaps and final sample age. This includes sampler/IPC overhead. The RSS target is <=85,000,000 bytes only with a complete run, gaps <=1,000 ms and final sample age <=1,000 ms; otherwise UNAVAILABLE. Driver memory is never used for this target. A missed target remains TARGET_MISSED. This Windows development machine is not a dedicated performance host.

Reports are new private JSON files under data/reports, ignored by Git and static serving. Console output gives their path and metrics only. The runner stops only its own child, waits for exit and checks directory ownership/nonlink boundaries before cleanup. It never touches a working database or an unrelated listener. See [STATUS.md](STATUS.md) for actual results; implementing a harness does not prove a target.

An external process termination can leave an owned disposable directory/dead lease. Confirm the exact recorded child PID is stopped before recovering that lease or removing its checked directory; never infer that from a closed terminal or delete another run's sidecars. An interrupted run establishes no benchmark result.

## Hosted preparation and remaining verification

Use [RENDER.md](RENDER.md) and the schema-validated render.yaml for the current proposed topology. Normal deploy:start has existing-file startup and a 25-second drain. The separately selected deploy:initialize command is the only deployment bootstrap path; ordinary install/build/start never initializes storage. Explicit deploy:maintenance runs only before the listener after the old disk-backed instance stops. No paid resource or auto-deployment is active from these files.

The application can bind HOST=0.0.0.0 and a supplied PORT. Nonloopback use requires explicit HTTPS FRONTEND_ORIGIN/API_ORIGIN; process environment wins over .env. PUBLIC_API_BASE_URL is the only exposed build value. Use exactly one backend process and one persistent database authority, with no worker replicas, ephemeral auto-seed or database downloads from a static site. Run initialization as an explicit private operation on the selected persistent storage. A hosted mount must resolve within the App's allowed private data tree.

The backend currently serves only explicit frontend page/shared roots and assets; generated dist is public-only for a separately selected static frontend. Neither is permission to publish the repository root. Build needs the locked Tailwind dev dependency. Keep backend, .env, node_modules and all data out of a static publish target. Do not change origins/cookie policy to work around a browser failure without verifying the resulting security behavior. Proxy headers remain untrusted.
